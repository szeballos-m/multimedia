Introducción al Software de Autoría

Herramientas de Autoría y Lógica

Una herramienta de autoría en entornos web locales (como XAMPP/Laragon + WordPress) permite integrar elementos gráficos, audio, video y contenidos interactivos en un producto final cerrado, sin requerir desarrollo de código complejo desde cero, utilizando plugins visuales de maquetación.

Introducción: El Enfoque WordPress para Sistemas Cerrados

A diferencia de una web abierta conectada a Internet, en un sistema cerrado local (como una terminal informativa, un tótem museístico o un soporte educativo autónomo en una PC sin red), WordPress se configura para comportarse como una aplicación stand-alone:

  • Sin conexión externa: Todo corre desde el servidor local (Apache/MySQL) instalado en la máquina mediante XAMPP, Laragon o UwAmp.

  • Navegación Restringida: Se eliminan los menús públicos de navegación abierta, los comentarios y los motores de búsqueda para forzar una estructura inalterable (tipo kiosco).

✓ Elementor: La Interfaz Visual (Equivalente al Canvas)

En lugar de trabajar sobre un lienzo vectorial flotante, trabajamos con el Page Builder Elementor.

  • Para qué sirve: Diseñar tótems, kioscos interactivos y pantallas de presentación táctiles con una estética profesional.

  • Fortaleza: Control total del diseño responsive, posicionamiento absoluto o de cuadrícula, y maquetación visual en tiempo real de cada "pantalla" (página estática).

✓ Arquitectura de Páginas: Sustituyendo a los "Frames"

Mientras que en software de animación se usan frames en una línea de tiempo, en WordPress cada pantalla del sistema cerrado es una Página Estática de WordPress o una Plantilla (Template) fija, interconectada mediante hipervínculos estructurados.

Resumen de la Lógica Interna en WordPress

Para dominar este entorno, debemos trasladar los tres pilares lógicos:

  1. El Lienzo (Canvas / Secciones de Elementor): Donde organizamos los contenedores, botones, imágenes y textos fijos de la pantalla.

  2. El Flujo Temporal (Orden de Páginas): En lugar de stop(); en una línea de tiempo, el sistema cerrado se controla desactivando la barra de navegación del theme y exigiendo botones de acción explícitos para cambiar de página (ej. "Ir a Inicio", "Siguiente").

  3. Interactividad y Enlaces (Hipervínculos fijos): Los botones de Elementor actúan como los triggers o disparadores que dirigen al usuario a nodos específicos de información.

Estructura de Pantallas y Navegación (Árbol vs. Malla)

En un sistema cerrado implementado en WordPress, la estructura se blinda mediante la configuración del plugin y del tema:

  1. Navegación Lineal / Árbol: Páginas conectadas estrictamente de forma secuencial (ej. Pantalla de Bienvenida $\rightarrow$ Selección de Categoría $\rightarrow$ Detalle). Se logra ocultando el menú global y colocando únicamente botones de avance/retroceso personalizados en cada página de Elementor.

  2. Navegación en Malla (Nodos): Uso de un menú fijo lateral o flotante (anclado mediante CSS/Elementor Pro) que permite saltar a secciones globales clave (ej. "Ayuda", "Menú Principal", "Emergencia") desde cualquier pantalla.

Gestión de Estados y Contenido Condicional en WordPress

Para simular la persistencia de datos o la "memoria" del sistema (equivalente a las variables globales):

  • Páginas de Agradecimiento o Estados (Conditional Display): Mediante widgets avanzados de Elementor (o plugins de visibilidad condicional), podemos hacer que ciertos bloques de contenido aparezcan o desaparezcan según la interacción previa del usuario (por ejemplo, si completó un formulario o hizo clic en una opción específica).

  • Optimización Táctil (Tótem): Al igual que en entornos interactivos puros, en pantallas táctiles locales no existe el estado hover (pasar el cursor por encima). Todo el diseño debe recaer en el estado activo/clic (mouseDown), garantizando botones grandes y zonas táctiles amplias.

Guía de Inicio Rápido: WordPress como Sistema Cerrado Local

1. Preparación del Entorno Local (XAMPP / Laragon / UwAmp)

  1. Inicia los servicios de Apache y MySQL en tu servidor local.

  2. Asegúrate de que WordPress esté instalado en una base de datos local limpia.

  3. Instala un tema minimalista y limpio (como Hello Elementor) para evitar elementos visuales heredados que interfieran con el diseño del kiosco.

2. Configuración de Pantallas (Páginas Estáticas)

En un sistema cerrado, no usamos "Entradas" (posts) de blog, sino Páginas:

  1. Ve al panel de WordPress $\rightarrow$ Páginas $\rightarrow$ Añadir nueva.

  2. Crea las páginas base del sistema (ej: 01_Inicio, 02_Menu_Principal, 03_Seccion_Multimedia, 04_Ayuda).

  3. En los ajustes de lectura de WordPress, configura la página estática de inicio para que el sistema abra directamente en 01_Inicio.

3. Maquetación con Elementor (El "Canvas" Visual)

  1. Abre cada página y haz clic en "Editar con Elementor".

  2. Configura el diseño de la sección en Ancho Completo (Full Width) y oculta el título de la página desde los ajustes de la rueda dentada de Elementor para lograr una pantalla limpia, sin barras de navegación web tradicionales.

  3. Arrastra contenedores, imágenes optimizadas y botones interactivos.

4. Creación de Botones e Hipervínculos Estrictos

Para mantener la naturaleza de estructura inalterable:

  1. Selecciona un botón en Elementor.

  2. En el campo Enlace, introduce la URL interna de la página de destino (ej. http://localhost/taller/menu-principal).

  3. Buena práctica: Evita abrir enlaces en nuevas pestañas (target="_blank"). Todo debe suceder dentro de la misma ventana de la aplicación local para no revelar el navegador.

5. Optimización de Multimedia Local

Dado que el sistema corre en local (USB o disco interno):

  • Imágenes: Sube los gráficos optimizados previamente en formatos ligeros (.webp o .png comprimidos) mediante herramientas libres como GIMP o Krita.

  • Videos y Audios: Inserta elementos multimedia locales utilizando el widget de Video/Audio nativo de Elementor, asegurando que los archivos estén alojados en la biblioteca de medios local de WordPress para evitar cualquier dependencia de internet.

6. Bloqueo del Entorno (Modo Kiosco Local)

Para que WordPress parezca una aplicación autónoma y no una web común:

  • Instala un plugin de seguridad o utiliza configuraciones CSS/JS para desactivar el clic derecho (evitando inspeccionar código o salir de la pantalla).

  • Oculta la barra superior de administración de WordPress para los usuarios comunes mediante la gestión de roles.

  • Utiliza el navegador en Modo Pantalla Completa (F11) o configura un acceso directo que abra el navegador directamente en la URL local del proyecto.

Comprobación y Testeo Local

  1. Abre tu navegador predeterminado y entra a la ruta local del proyecto (ej: http://localhost/tu-proyecto/).

  2. Realiza pruebas de usabilidad táctil o con mouse: verifica que los enlaces no dejen callejones sin salida y que la velocidad de carga de los recursos locales sea inmediata.
